Мета заняття

Підготувати ваш full-stack застосунок до production і задеплоїти його на Vercel. До кінця практики у вас буде:

  • Публічний URL вигляду https://your-app.vercel.app — працюючий застосунок в інтернеті
  • Оптимізовані зображення через next/image
  • SEO-готова сторінка: title-template, OpenGraph, Twitter Cards
  • Convention-based robots.txt та sitemap.xml через Next.js
  • Якісний README.md з демо-посиланням, скріншотами та інструкціями
  • Auto-deploy на push у main — кожен коміт автоматично деплоїться

1. Підготовка проєкту до деплойменту

Стартуємо з результату тижня 12: повний CRUD з RHF + Zod, авторизація, RBAC, безпека, toast-нотифікації. Перевіряємо, що проєкт готовий до production-білда.

Завдання 1.1: Створити робочу гілку

  1. Перейти у директорію вашого проєкту: cd шлях/до/вашого-проекту
  2. Переконатися, що ви на основній гілці: git status
  3. Створити робочу гілку для тижня 13: 
    git checkout -b LR13

Завдання 1.2: Перевірити .env.local.example

Файл .env.local.example повинен містити всі змінні, які потрібні для запуску, без реальних значень. Це шаблон, який бачитиме той, хто склонує ваш репозиторій. 

# .env.local.example
MONGODB_URI=mongodb+srv://YOUR_USER:YOUR_PASSWORD@cluster0.xxxxx.mongodb.net/yourdb
NEXTAUTH_SECRET=GENERATE_WITH_openssl_rand_base64_32
NEXTAUTH_URL=http://localhost:3000
NEXT_PUBLIC_SITE_URL=http://localhost:3000

Якщо у вашому .env.local.example чогось не вистачає — додайте.

Завдання 1.3: Перевірити .gitignore

Файл .env.local з реальними секретами не повинен бути в git. Перевірте .gitignore: 

cat .gitignore | grep .env

Має бути рядок (приходить з create-next-app):

# env files (can opt-in for committing if needed)
.env*

Якщо це є — .env.local не комітиться, все ок.

Завдання 1.4: Локальний production-білд

Це найважливіша перевірка перед деплоєм. Vercel запускає той самий next build, що й ви локально. 

npm run build

Якщо білд проходить (бачите «Compiled successfully» і таблицю маршрутів) — можна деплоїти. Якщо ламається — виправляйте помилки тут, а не в Vercel.

⚠️ Якщо білд не проходить
  • Type errors — виправте відповідно до повідомлення
  • Module not found — пропущена залежність, npm install
  • Environment variable required — не використовуйте process.env.X у глобальному scope без default-значення (під час білда змінні можуть бути недоступні)
🔍 Чек-точка

Перед переходом далі у вас має бути:

  • Гілка LR13 створена
  • .env.local.example повний і актуальний
  • npm run build проходить локально без помилок

2. Оптимізація зображень з next/image

Знайдемо у проєкті місця, де є <img> або велика hero-секція без картинки, і використаємо next/image.

Завдання 2.1: Знайти існуючі <img>

grep -rn "<img" app components --include="*.js" --include="*.jsx"

Якщо знайшли — замініть на <Image> з next/image.

Завдання 2.2: Hero-картинка на головній сторінці

Якщо у вас на головній є hero-секція з градієнтом, додайте справжню фонову картинку. Беремо безкоштовне зображення з Unsplash — його URL стабільний: 

https://images.unsplash.com/photo-XXXXXXXXXXXXX?auto=format&fit=crop&w=1600&q=80

Для своєї теми проєкту знайдіть тематичне зображення на unsplash.com (бібліотека, фітнес, готель тощо), скопіюйте URL.

Завдання 2.3: Замінити hero на <Image>

Відкрийте app/page.js і додайте hero-секцію з оптимізованим зображенням:

import Image from "next/image";

<section className="relative h-[480px] flex items-center justify-center overflow-hidden">
  <Image
    src="https://images.unsplash.com/photo-XXX?auto=format&fit=crop&w=1600&q=80"
    alt="Опис вашого зображення"
    fill
    priority
    sizes="100vw"
    className="object-cover"
  />
  {/* Темний overlay для читабельності тексту */}
  <div className="absolute inset-0 bg-gradient-to-r from-amber-900/80 to-amber-700/60" />
  <div className="relative container mx-auto px-4 text-center text-white">
    <h1 className="text-5xl font-bold mb-4">Назва вашого проєкту</h1>
    {/* ... решта вмісту hero ... */}
  </div>
</section>

Звертаємо увагу:

  • fill — картинка заповнює батьківський контейнер
  • Батько має position: relative (через клас relative) і фіксовану висоту (h-[480px])
  • priority — картинка above-the-fold, завантажується першою
  • sizes="100vw" — підказка браузеру: картинка займає всю ширину viewport
  • object-cover — картинка обрізається, не розтягується

Завдання 2.4: Дозволити Unsplash у next.config.mjs

Без цього отримаєте помилку "Invalid src prop... hostname is not configured": 

// next.config.mjs
const nextConfig = {
  // Тиждень 13: дозволені домени для next/image
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "images.unsplash.com",
      },
    ],
  },

  // Тиждень 10: безпекові HTTP-заголовки
  async headers() { /* ... */ },
};

Завдання 2.5: Перевірити локально

  1. Перезапустити dev-сервер (Ctrl+C → npm run dev) — зміни в next.config.mjs вимагають рестарту
  2. Відкрити http://localhost:3000
  3. Hero-картинка має з'явитися
  4. DevTools → Network → Img — побачите, що Next.js обслуговує WebP через свій ендпоінт /_next/image?url=...

3. Розширення metadata + OpenGraph

Зараз ваш app/layout.js має базові title + description. Розширимо до повноцінного production-набору з OpenGraph і Twitter Cards.

Завдання 3.1: Створити OG-зображення

Вам потрібна картинка 1200×630px (стандарт OG) у public/. Найпростіший варіант — SVG із градієнтом і назвою: 

// public/og-image.svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1200 630" width="1200" height="630">
  <defs>
    <linearGradient id="bg" x1="0" y1="0" x2="1" y2="1">
      <stop offset="0%" stop-color="#92400e" />
      <stop offset="100%" stop-color="#d97706" />
    </linearGradient>
  </defs>
  <rect width="1200" height="630" fill="url(#bg)" />
  <text x="600" y="280" font-family="system-ui" font-size="120" font-weight="700"
        fill="#ffffff" text-anchor="middle">Назва проєкту</text>
  <text x="600" y="380" font-family="system-ui" font-size="36"
        fill="#fef3c7" text-anchor="middle">Слоган</text>
</svg>

Для свого проєкту змініть градієнт під свою тему (зелений для бібліотеки, синій для готелю тощо) і вставте назву.

Завдання 3.2: Розширити metadata в app/layout.js

// app/layout.js
const siteUrl = process.env.NEXT_PUBLIC_SITE_URL || "http://localhost:3000";

export const metadata = {
  metadataBase: new URL(siteUrl),
  title: {
    default: "Назва проєкту",
    template: "%s | Назва проєкту",
  },
  description: "Опис вашого проєкту в одному реченні.",
  keywords: ["ключове-слово-1", "ключове-слово-2"],
  authors: [{ name: "Назва проєкту" }],
  openGraph: {
    type: "website",
    locale: "uk_UA",
    url: "/",
    siteName: "Назва проєкту",
    title: "Назва проєкту",
    description: "Опис.",
    images: [
      {
        url: "/og-image.svg",
        width: 1200,
        height: 630,
        alt: "Назва проєкту",
      },
    ],
  },
  twitter: {
    card: "summary_large_image",
    title: "Назва проєкту",
    description: "Опис.",
    images: ["/og-image.svg"],
  },
};

Завдання 3.3: Додати title для публічних сторінок

Для кожної публічної сторінки (наприклад, /menu, /about) додайте власний title — шаблон з root layout автоматично додасть «| Назва проєкту»: 

// app/menu/page.js
export const metadata = {
  title: "Меню",
  description: "Перегляньте повне меню кав'ярні.",
};

Зробіть те саме для /about і будь-яких інших публічних сторінок.

Завдання 3.4: generateMetadata для динамічних сторінок

У вас уже є app/menu/[id]/page.js (або аналогічний для вашого варіанту) з generateMetadata з тижня 7. Перевірте, що він повертає title = назві з БД, і опціонально розширте openGraph.title + openGraph.description. 

export async function generateMetadata({ params }) {
  const { id } = await params;
  await dbConnect();
  const item = await Item.findById(id).lean();
  if (!item) return { title: "Не знайдено" };

  return {
    title: item.name,
    description: item.description,
    openGraph: {
      title: item.name,
      description: item.description,
    },
  };
}
🔍 Перевірка
  1. Перезапустити dev-сервер
  2. Відкрити будь-яку сторінку, у браузері: View Page Source (Ctrl+U)
  3. У <head> побачите:
<title>Меню | Назва проєкту</title>
<meta name="description" content="..."/>
<meta property="og:title" content="..."/>
<meta property="og:image" content="http://localhost:3000/og-image.svg"/>
<meta name="twitter:card" content="summary_large_image"/>

4. robots.js + sitemap.js

Завдання 4.1: Створити app/robots.js

// app/robots.js
const siteUrl = process.env.NEXT_PUBLIC_SITE_URL || "http://localhost:3000";

export default function robots() {
  return {
    rules: [
      {
        userAgent: "*",
        allow: "/",
        disallow: ["/dashboard/", "/api/", "/login", "/register"],
      },
    ],
    sitemap: `${siteUrl}/sitemap.xml`,
  };
}

Заборонили ботам індексувати приватні маршрути. Допустили все інше.

Завдання 4.2: Створити app/sitemap.js

// app/sitemap.js
import dbConnect from "@/lib/db";
import Item from "@/lib/models/Item";
// ^^^ замініть на свою основну модель (Book, Property, Vacancy тощо)

const siteUrl = process.env.NEXT_PUBLIC_SITE_URL || "http://localhost:3000";

export default async function sitemap() {
  const staticRoutes = [
    { url: `${siteUrl}/`, lastModified: new Date(), changeFrequency: "weekly", priority: 1 },
    { url: `${siteUrl}/menu`, lastModified: new Date(), changeFrequency: "daily", priority: 0.9 },
    { url: `${siteUrl}/about`, lastModified: new Date(), changeFrequency: "monthly", priority: 0.5 },
  ];

  let dynamicRoutes = [];
  try {
    await dbConnect();
    const items = await Item.find({ available: true }).select("_id updatedAt").lean();
    dynamicRoutes = items.map((d) => ({
      url: `${siteUrl}/menu/${d._id}`,
      lastModified: d.updatedAt || new Date(),
      changeFrequency: "weekly",
      priority: 0.7,
    }));
  } catch {
    // якщо БД недоступна під час білда — повертаємо лише статичні
  }

  return [...staticRoutes, ...dynamicRoutes];
}
🔍 Перевірка
  1. Відкрити http://localhost:3000/robots.txt — побачити текстовий robots
  2. Відкрити http://localhost:3000/sitemap.xml — побачити XML з усіма URL

git add .

Зробіть PR або merge напряму:

Завдання 6.3: Реєстрація на Vercel

  1. Відкрити vercel.com/signup
  2. Натиснути Continue with GitHub
  3. Авторизувати Vercel доступ до вашого GitHub-акаунту

Завдання 6.4: Імпорт проєкту

  1. На головній Vercel Dashboard — Add New… → Project
  2. У списку GitHub-репозиторіїв знайти ваш — натиснути Import
  3. Vercel автоматично визначить, що це Next.js. Не змінюйте Build Command, Output Directory, Install Command — усе має бути за замовчуванням

Завдання 6.5: Налаштувати Environment Variables

У секції Environment Variables додайте всі змінні з вашого .env.local:

Key Value
MONGODB_URI ваш Atlas connection string
NEXTAUTH_SECRET той самий, що й локально
NEXTAUTH_URL тимчасово залишіть http://localhost:3000 — оновимо після деплою
NEXT_PUBLIC_SITE_URL тимчасово http://localhost:3000

Завдання 6.6: Whitelist у MongoDB Atlas

Vercel використовує динамічні IP. Якщо у MongoDB Atlas обмежено доступ — деплой задеплоїться, але API крутитиме 500-помилки.

  1. Відкрити cloud.mongodb.com
  2. Зайти у ваш кластер → Network Access
  3. Add IP Address → Allow Access from Anywhere (0.0.0.0/0)
  4. Підтвердити (зміна застосовується через 1–2 хвилини)
Чому це безпечно для навчального проєкту: MongoDB все одно вимагає логін/пароль з connection string. 0.0.0.0/0 — це лише про мережевий шар.

Завдання 6.7: Перший деплой

  1. Натиснути Deploy
  2. Чекати 1–2 хвилини, поки йде білд
  3. Після успіху Vercel показує preview скріншот і URL вигляду https://your-project.vercel.app
⚠️ Якщо білд впав
  • Натисніть View Build Logs — шукайте останню помилку
  • Виправіть локально, push — новий коміт автоматично запустить новий білд
  • Якщо помилка «Module not found» — перевірте package.json
  • Якщо process.env.X is undefined — забули додати змінну в Settings

Завдання 6.8: Оновити NEXTAUTH_URL і NEXT_PUBLIC_SITE_URL

Тепер у вас є реальний production-URL. Скопіюйте його (наприклад, https://my-app-abc123.vercel.app):

  1. У Vercel Dashboard → ваш проєкт → Settings → Environment Variables
  2. Знайти NEXTAUTH_URL, натиснути Edit, замінити значення на ваш Vercel-URL, зберегти
  3. Те саме для NEXT_PUBLIC_SITE_URL
  4. Перейти у вкладку Deployments, на останньому деплої — ... → Redeploy

7. Перевірка production

Завдання 7.1: Smoke test основних flows

  1. Відкрити ваш Vercel-URL у браузері
  2. Зареєструвати нового користувача (через /register)
  3. Залогінитися
  4. Створити запис основної сутності
  5. Створити запис другої (зв'язаної) сутності
  6. Видалити запис
  7. Зайти як admin (треба зробити користувача admin вручну в Mongo Compass)
  8. Перевірити, що сторінка /dashboard/users доступна

Завдання 7.2: Перевірити SEO та зображення

  1. Відкрити будь-яку публічну сторінку, View Page Source (Ctrl+U)
  2. Знайти <title>, <meta property="og:..."> — вони мають бути з абсолютними URL (з вашим Vercel-доменом)
  3. Відкрити https://your-app.vercel.app/robots.txt — перевірити, що sitemap-URL правильний
  4. Відкрити https://your-app.vercel.app/sitemap.xml — перевірити XML
  5. DevTools → Network → Img — hero-зображення має приходити через /_next/image?... у форматі WebP

Завдання 7.3: Перевірити OpenGraph через зовнішній сервіс

Відкрити opengraph.xyz, вставити ваш Vercel-URL, побачити preview-картку для соцмереж. Якщо OG-картинка показується — metadata налаштовано правильно.

Завдання 7.4: Переглянути логи у Vercel

  1. Vercel Dashboard → ваш проєкт → Logs
  2. Зробіть кілька запитів до застосунку
  3. У логах побачите HTTP-запити, статус-коди, час відповіді
  4. Якщо щось 500-тить — тут буде stack trace

Завдання 7.5: Оновити README з реальним демо

  1. Зробіть 3-5 скріншотів вашого застосунку (головна, дашборд, форма, деталі)
  2. Покладіть їх у public/screenshots/ або (краще) додайте у README через GitHub-завантаження зображень (drag-and-drop у markdown editor)
  3. Замініть placeholder «_додати посилання_» на реальний Vercel-URL
  4. Commit + push
  5. Перевірте, що README на GitHub виглядає добре, скріншоти показуються, посилання працюють
🔍 Чек-точка
  • Застосунок доступний за публічним URL
  • Реєстрація + логін працюють у production
  • CRUD працює у production
  • /robots.txt, /sitemap.xml віддаються
  • OG-теги абсолютні (з вашим доменом)
  • README з демо-посиланням і скріншотами

8. Збереження та завантаження на GitHub

Усі зміни вже на GitHub (для деплою це обов'язково). Цей крок — формальний: перевірити стан, переконатися, що нічого не залишилося не закомічене.

Завдання 8.1: Фінальна перевірка

git status

Має бути nothing to commit, working tree clean. Якщо є зміни (наприклад, оновлений README зі скріншотами) — commit і push:

git add .
git commit -m "Add screenshots and demo link to README"
git push origin main

Кожен push автоматично запускає новий Vercel-деплой.

Завдання 8.2: Перевірити автоматичний redeploy

  1. Vercel Dashboard → Deployments
  2. Побачити новий deployment з вашим коміт-message
  3. Через 1–2 хвилини він стає Ready

Бонусні завдання

Бонусні завдання не є обов'язковими і не впливають на наступні практичні роботи. Виконуються за бажанням для додаткових балів.

Бонус 1: Custom domain

Купити дешевий .dev або .tech домен (10–15 USD/рік) і підключити до Vercel: Settings → Domains. Налаштувати DNS-записи у реєстратора (зазвичай A-record + CNAME). Vercel автоматично видасть Let's Encrypt SSL.

Бонус 2: Динамічна OG-картинка

Замість статичного og-image.svg створити app/opengraph-image.js або app/menu/[id]/opengraph-image.js — Next.js згенерує OG-image на льоту через ImageResponse (з тексту, кольорів, fonts).

Бонус 3: Vercel Analytics

У Vercel Dashboard → Analytics. Безкоштовний tier для базових метрик. Встановити @vercel/analytics і додати <Analytics /> у root layout. Через кілька годин побачите Core Web Vitals реальних користувачів.

Бонус 4: Strict IP whitelist для MongoDB

Замінити 0.0.0.0/0 на конкретні Vercel IP-діапазони (доступні у Vercel docs). Безпечніше, але вимагає періодичного оновлення, якщо Vercel змінить діапазони.

Бонус 5: Lighthouse CI

Запустити Lighthouse audit (вкладка Lighthouse у Chrome DevTools) на ваш Vercel-URL. Ціль: 90+ за всіма метриками (Performance, Accessibility, Best Practices, SEO). Якщо є проблеми — виправити (alt-теги, контраст, semantic HTML).

Бонус 6: Sentry або інша error monitoring

Підключити Sentry для моніторингу помилок у production. Безкоштовний tier дає 5K events/month. Бачитимете кожну помилку з stack trace, user agent, breadcrumbs.
